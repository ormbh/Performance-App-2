## Evidence and limits

Chromium rendered current v144 with the frozen illustrative workbook (SHA256 recorded in evidence.json). The before captures come from the actual app. After captures use temporary browser-only presentation changes. Four result identities, full source records, filters and sorting were compared and remained identical. The existing first-record details action opened successfully. Proposed layouts were checked at 1440px, 390px and 320px without whole-page overflow. The three boards were visually inspected for Arabic, direction, spacing and accurate scope.

The selection example is an independent specimen, not an active filter on the four-result query. These screenshots are viewport crops, not a statement that all result rows fit on one screen. Proposed options-menu behavior, complete keyboard/screen-reader support, exports and production workbook reconciliation are not validated by these static concepts. Implementation would require those checks.
