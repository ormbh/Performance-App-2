TEC Apple-Inspired Design — shared workspace standard

Revision 3 proposal — 11 October 2026. Prepared for review of filters, menus, printing, buttons, icons, headers and footers. Revision 2's approved typography, exact palette, status badges, data meanings and dashboard composition remain the baseline. The new arrangements and interaction details below are proposals, not an assertion that the released v129 app has changed.

Approved Revision 2, retained in full. Before/after gallery. All public examples use illustrative data. The supplied operational PDF is a read-only diagnostic reference, not a source for public specimen records or an instruction to change calculations.

Only one nonmodal popup is open at a time. Outside pointer dismissal must allow the newly clicked control to receive focus; do not force focus back after every outside click. Existing outside/Escape dismissal already passes in v129; standardization must preserve that working behavior. New proposal demos are not certification of the released app or a completed screen-reader review.

9. Rules to save and apply after review

  1. Use the approved fonts, sizes, exact colors, status labels and source definitions.
  2. Share component roles and their states, not just colors: actions, fields, navigation, informational badges, popups, disclosures and dialogs are distinct.
  3. Keep report identity, navigation, task actions and filter scope in predictable places. Retain the Google search-home composition as the deliberate exception.
  4. Show the same three core scope fields on report pages where applicable. Extras are progressive disclosure; collapsing them never clears selected values.
  5. Preserve live filtering, OR-within/AND-across, source keys/aliases and dependency validation. Do not silently transfer scope across unrelated pages.
  6. Reset only filters in the proposed new implementation; retain unrelated dates, data, notes and preferences. Make this explicit when replacing broader defaults.
  7. Every action/option/close/remove control has at least 44px target and a correct name/state. Use existing 20px icons consistently.
  8. Keep field hover Paper; do not reuse button hover fills for inputs or selectors.
  9. Use one popup at a time with outside/Escape dismissal. Keyboard returns focus; outside click allows natural focus. Modal sheets/dialogs contain focus.
  10. Use one report print label and one shared settings surface; optional settings do not create an extra approval or data-commit step.
  11. Preserve the independent print scale, source scope, row membership/order, zero/missing meanings and valid history arrows. Add pages instead of shrinking.
  12. Every print page has report/date context and page numbering; repeated column headings remain readable and do not contain a duplicate full masthead.
  13. Entity filter details stay screen-only while the selected scope continues to determine printed figures and rows.
  14. Header/footer margins align, metadata stays readable and file names wrap. No fixed footer may cover content. Preserve exact legal wording.
  15. Inspect the monthly workspace first at 100% browser zoom, then reuse the shared components in projects/search/upload/reports. Test desktop/mobile, keyboard, long option lists, disabled/busy/errors and every actual PDF page. A prototype review does not prove live data parity or accessibility certification.
